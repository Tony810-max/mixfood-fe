## Routing policy
1. Per task, inspect the *relevant* available inventory (Skill listing, `/mcp`, files above). Do not use every tool.
2. Pick all useful, non-conflicting capabilities. UI/UX work: evaluate ui-ux-pro-max, impeccable, taste (by file in Claude), ui-styling, and any a11y/review tools; combine direction -> implementation -> critique. Settle conflicts in favor of [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) and the user's request.
3. Read the chosen skill's real `SKILL.md` before running it; follow its invocation, prerequisites and permissions.
4. MCP only for authorized, purpose-matched actions. Read-only first; ask before side effects (writes, posts, uploads, installs). Do not send repo source or data to external services without approval.
5. If a capability is missing, inactive or conflicts with repo rules, say so and use the repo-native fallback. Never pretend to invoke it.
6. Do not install plugins, packages, skills or MCP servers; do not edit global or permission settings.
7. Record used / not used / unavailable in report section VI ([REPORT_TEMPLATE.md](REPORT_TEMPLATE.md)).
